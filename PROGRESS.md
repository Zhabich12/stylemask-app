# Ход работы stylemask

## Что строим

Приложение, которое **переписывает** текст пользователя так, чтобы по стилю нельзя было понять, кто автор (вариант A — защита от стилометрии). Можно загружать примеры своего стиля и целевые стили (в т.ч. стили других людей).

Продукт — это **переписчик** (локальная LLM). Классификаторы («угадыватели автора», «линейки») — не продукт, а **проверка**: ими мы меряем, сработало ли переписывание.

```
твой текст ──► переписчик (LLM) ──► новый текст ──► линейки: «чей это?»
                                                   └► сравнение смысла: «то же самое сказано?»
цель: линейки не различают авторов, смысл сохранён
```

## Правила

- Переписки и всё, что из них получено (`data/`), хранятся **только локально**: не в git, не во внешних API. Pre-commit хук в `.githooks/` блокирует случайные коммиты.
- Эксперименты на реальных переписках — только через локальные модели (LM Studio, `localhost:1234`).
- Текст переписок Claude не выводит в чат (иначе он уходит в API Anthropic) — только метрики.

- LM Studio: `lms server start`; модели `qwen/qwen3.5-4b` (основная, влезает в VRAM), `google/gemma-4-e2b` (медленная), `text-embedding-nomic-embed-text-v1.5` (смысл).
- Для Qwen/Gemma передаём `reasoning_effort: "none"` — иначе модель «думает» и всё в 10–20 раз медленнее.
- Железо: 16 ГБ RAM (свободно обычно <1 ГБ — фоновые прогоны может убить система), RTX 3050 Laptop 4 ГБ VRAM.
- GitHub: публичный репозиторий Zhabich12/stylemask-app (remote `public`, сюда идут коммиты). Старый приватный Zhabich12/stylemask (remote `private`) с полной историей не трогаем; локально она в ветке `private-history`. Коммиты подписываются noreply-адресом. git авторизован через `gh auth setup-git`.
- Скиллы проекта: `stylometric-fingerprinting`, `scikit-learn`. MCP: `huggingface` (нужен вход через `/mcp`).

## Данные

- Telegram: 3 экспорта → `data/fragments.jsonl` (фрагменты ~400 символов). Пользователь 1260, друг A 323, друг B 272; друг C — 8 (не входит).
- Пикабу: датасет IlyaGusev/pikabu (HF), шард 00 → 50 самых активных комментаторов, 8865 фрагментов → `data/pikabu_fragments.jsonl`. Сайт напрямую не парсим (комментарии через `/ajax/`, закрыт в robots.txt).

## Линейки (attackers)

| Линейка | Что видит | 3 чат-автора | 53 автора |
|---|---|---|---|
| ngram | символьные + словесные n-граммы, полный текст | 98% | 82% |
| style | то же, значимые слова замаскированы | 96% | 74% |
| morph | n-граммы частей речи (pymorphy3) + пунктуация | 90% | 63% |
| delta | Burrows's Delta по 300 частым словам | 78% | 11% (коротким фрагментам не годится) |

Balanced accuracy на исходных текстах. Случайно: 33% / 2%.

## Как правильно мерить (важно)

Сначала мерили «узнаётся ли пользователь» — это **неверно**: переписанный текст друга линейка тоже относила к пользователю (24/30). Пользователь — «корзина по умолчанию», куда падает всё обезличенное.

Правильно (`scripts/experiment.py`): переписать тексты **всех** авторов одним методом и мерить balanced accuracy:
- **static** — линейки обучены на оригиналах, проверяются на переписанном;
- **adaptive** — линейка обучена на *переписанных* текстах (5-fold) — противник, который знает наш инструмент. Главная метрика;
- **meaning** — косинус эмбеддингов оригинал/переписанное.

Сравнение «53 автора» смешано с разницей площадок (чат vs комментарии), поэтому основные опыты — на 3 чат-авторах.

## Результаты экспериментов (3 чат-автора, 40 фрагм. каждого, Qwen3.5 4B)

| Метод | style | morph | delta | ngram | adaptive style | adaptive morph | смысл |
|---|---|---|---|---|---|---|---|
| оригиналы | 96% | 87% | 75% | 98% | 87% | 81% | — |
| neutral | 55% | **39%** | 65% | 61% | 78% | 67% | 0.89 |
| persona (автор с Пикабу, 6 примеров) | 67% | **39%** | 73% | 91% | 72% | 70% | 0.93 |
| loop | _не досчитан: прогон убит системой из-за нехватки RAM_ | | | | | | |

Случайно — 33%.

### Ранние опыты (до правильной метрики)

- Gemma 4 E2B, мягкий промпт: пользователь узнан 95% → 95%, ~28 с/фрагмент.
- Qwen neutral vs 53 автора: пользователь 90% → 0% — но это эффект смены площадки, на 3 чат-авторах 97% → 100% (корзина по умолчанию).

## Выводы

- Qwen3.5 4B в 15–20 раз быстрее Gemma на этом железе и прячет лучше.
- Морфология после переписывания падает почти до случайного (39%) — модель полностью перестраивает фразы.
- **Но адаптивный противник всё ещё различает авторов (67–78%)**. Переписывание пока оставляет «отпечаток» — частично это может быть содержание (у каждого чата свои темы), частично стиль.
- Персона с Пикабу почти не помогает и хуже по n-граммам (91%): модель больше копирует исходные слова. Возможно, стиль комментариев плохо ложится на чатовые сообщения.

## Решение 2026-10-24

Защиту от адаптивного противника (знает про инструмент) **пока не разрабатываем** — решение пользователя. Ориентир сейчас — статические линейки (style, morph, ngram); adaptive оставляем в отчёте только для информации.

## Окно приложения (2026-10-24)

`stylemask.bat` (двойной клик) или `stylemask gui`. Tkinter, без новых зависимостей. Режимы: нейтрально / как другой автор / как другой автор + проверка (loop). Кнопка запуска LM Studio, если сервер не поднят. Первый запуск loop обучает линейку (~30 с), дальше она из кэша `data/cache/`.

Смоук-тест на тестовой фразе: neutral 4 с, persona 3 с, loop 36 с (с обучением линейки).
**Найдено:** в neutral модель **исказила смысл** («очереди бесконечные» → «очередей вообще не было»). Средний косинус смысла 0.89 такие инверсии не ловит.

## Горячая клавиша (2026-10-24)

В любой программе: курсор в поле ввода → **Ctrl+Alt+Q** — текст поля заменяется переписанным; **Ctrl+Alt+Z** — вернуть исходный. Настройки (режим, персона, «всё поле / только выделенное», сочетания) — вкладка «Настройки», сохраняются в `stylemask.toml`.
Реализация (`src/stylemask/hotkey.py`): Win32 через ctypes, без хуков и без записи нажатий — RegisterHotKey + выделить/копировать/вставить, буфер обмена пользователя восстанавливается. Если за время переписывания окно сменилось — не вставляем, кладём результат в буфер.
Ctrl+Alt+R на этой машине занят другой программой → по умолчанию Ctrl+Alt+Q.
Проверено автоматически: регистрация/срабатывание/перерегистрация сочетаний, буфер обмена (Unicode, эмодзи). **Не проверено автоматически**: замена текста в реальном поле — Windows не даёт фоновому процессу забрать фокус; нужна ручная проверка (Блокнот, Telegram).

## Переписчик v2 (2026-10-24, конец сессии)

Против потери смысла: заметки-факты от первого лица → сообщение по заметкам (оригинальные слова модель не видит); температура 0.3; проверка смысла той же моделью + до 2 повторов, иначе предупреждение «⚠ Перечитай» (и звук в окне).
Под конкретного человека: карточка стиля (`style_card`: регистр, длина строк, пунктуация, характерные слова) + 15 примеров, похожих по смыслу (`ExamplePicker`, эмбеддинги nomic). Стили из Telegram: кнопка в окне или `stylemask add-style <папка> --author "<имя>"` → `data/custom_styles.jsonl` (персона `tg:<имя>`).
Ручная проверка на тестовой фразе: смысл сохраняется в neutral и persona; скорость 5–12 с вместо 2–4.
Индикатор прогресса: окошко в правом нижнем углу поверх всех окон («stylemask · Пишу (2/3) · 4 с», потом «✓ готово» / «⚠ перечитай» / «✗ ошибка») + полоса в главном окне. Окошко не забирает фокус (проверено тестом; Tk активирует окно при каждом показе, поэтому оно показывается один раз за краем экрана и дальше только двигается).
**Не сделано:** сравнение v1 vs v2 на 120 фрагментах прервано по просьбе пользователя. Запуск:
`stylemask experiment --method neutral --legacy --attackers style,morph,ngram` (и `persona`, и без `--legacy`) — v1 берётся из кэша, v2 считается заново (~30–60 мин всего).

## Переписчик v3 (2026-10-24)

Пользователь: v2 «не ощущается, что пишешь сообщение — солянка из того, как человек отвечает и сам задаёт вопрос».
Причины: (1) шаг «заметки → сообщение» терял роли (кто кого спрашивает); (2) примеры, подобранные по теме, — куски чужих диалогов, модель тащила их содержание и роли; (3) модель иногда *отвечала* на сообщение («прости, я не могу прислать конспект, я генеративная модель»).
v3: перефразирование предложение за предложением с сохранением ролей; сообщение обёрнуто как «это не вопрос к тебе»; примеры — отдельные короткие сообщения человека, случайные, «только для манеры»; словечки — только «манерные» части речи (частицы, междометия, наречия), без тем; оформление (регистр, точки в конце, разбивка на строки) применяется кодом (`SurfaceProfile`); проверка смысла теперь ловит смену ролей и ответ вместо пересказа. ~2 с на сообщение.
Остаётся: модель на 4B иногда ломает грамматику/род («ты вольна?»), и проверка смысла той же моделью пропускает часть искажений.

## Следующие шаги

0. **Базовая разметка датасета перед добавлением стиля** (идея пользователя): каждое сообщение человека помечать типом — вопрос, ответ, рассказ, просьба, реакция и т.п. Тогда примеры для промпта можно подбирать того же типа, что и переписываемое сообщение (вопрос — по его вопросам), и модель не смешивает «как он отвечает» с «как он спрашивает».

1. **Проверка смысла, которая ловит искажения** (отрицания, перевёрнутые факты) — напр. NLI-модель (openjev-подобная) или проверка той же LLM «совпадает ли смысл?» + повтор при провале.
2. Досчитать `loop` (`stylemask experiment --method loop`) — при свободной памяти (закрыть браузер и т.п.).
3. Поднять ngram после переписывания (сейчас 61–91%): модель копирует исходные слова.
4. Персоны из чатовых данных (групповые чаты) вместо комментариев Пикабу.
5. Отложено: защита от адаптивного противника, анонимизация содержания.
